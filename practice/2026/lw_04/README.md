# Лабораторная работа №04. Реализация механизмов безопасности и отказоустойчивости в распределенной системе

### 🎯 Цель работы
Разработать распределенную систему, обеспечивающую защищенную передачу данных с использованием взаимной аутентификации (mTLS) и симметричного шифрования, а также продемонстрировать механизмы отказоустойчивости (failover) через автоматическое переключение между узлами.

### 📋 Задачи
1.  **Настройка PKI.** Сгенерировать сертификаты X.509 для центра сертификации (CA), серверов и клиентов.
2.  **Обеспечение безопасности.** Реализовать HTTPS-соединения с взаимной аутентификацией (mTLS) и шифрование полезной нагрузки алгоритмом Fernet.
3.  **Разработка компонентов.** Реализовать серверы обработки данных, клиентское приложение и координатор (балансировщик нагрузки).
4.  **Реализация отказоустойчивости.** Настроить логику автоматического перенаправления запросов на резервный сервер при недоступности основного.
5.  **Выполнение индивидуального задания.** Расширить функциональность системы согласно варианту.

### 🛠 Инструменты и технологический стек
*   **ОС:** Ubuntu 20.04 LTS (или аналогичная Unix-like система / WSL).
*   **Язык программирования:** Python 3.8+.
*   **Библиотеки:**
    *   `Flask` — веб-фреймворк для создания серверов.
    *   `requests` — для выполнения HTTP-запросов.
    *   `cryptography` — для реализации шифрования Fernet и работы с SSL.
*   **Инструменты безопасности:** `OpenSSL` — для генерации ключей и сертификатов.

### 📚 Теоретическая часть

#### Архитектура системы
Система состоит из трех типов компонентов:
1.  **Клиент.** Шифрует данные симметричным ключом и отправляет их координатору. Использует клиентский сертификат для аутентификации.
2.  **Координатор (Load Balancer).** Принимает HTTP-запросы от клиента и перенаправляет их на доступные серверы по HTTPS. Отслеживает состояние серверов.
3.  **Серверы (Workers).** Принимают защищенные соединения (HTTPS + mTLS), расшифровывают данные и выполняют бизнес-логику.

**Схема потоков данных:**
```
┌─────────┐         ┌──────────────┐         ┌──────────┐
│ Клиент  │ ──────> │ Координатор  │ ──────> │ Сервер 1 │
│         │  HTTP   │ (Порт 8000)  │  HTTPS  │ (Порт    │
└─────────┘         │              │         │  5001)   │
                    │              │         └──────────┘
                    │              │         
                    │              │         ┌──────────┐
                    │              │ ──────> │ Сервер 2 │
                    │              │  HTTPS  │ (Порт    │
                    └──────────────┘         │  5002)   │
                                             └──────────┘
```

#### Ключевые технологии
*   **mTLS (Mutual TLS).** Протокол, требующий наличия сертификата как у сервера, так и у клиента. Гарантирует, что обе стороны являются доверенными.
*   **Fernet.** Система симметричного шифрования (на основе AES), гарантирующая конфиденциальность и целостность сообщения.
*   **Отказоустойчивость.** Способность системы продолжать работу при выходе из строя отдельных компонентов (в данном случае — переключение на Server 2 при падении Server 1).

### 💻 Практическая часть

#### Шаг 1. Подготовка окружения
Установите необходимые системные пакеты и библиотеки Python:
```bash
sudo apt update && sudo apt install python3 python3-pip python3-venv openssl -y
python3 -m venv venv
source venv/bin/activate
pip install flask cryptography requests
```

#### Шаг 2. Генерация ключей и сертификатов (PKI)
Создайте скрипт `generate_certificates.sh` и сгенерируйте:
1.  Корневой сертификат (CA).
2.  Сертификат и ключ сервера (подписанные CA).
3.  Сертификат и ключ клиента (подписанные CA).

```bash
chmod +x generate_certificates.sh
```
```bash
./generate_certificates.sh
```

*Результат:* файлы `ca_cert.pem`, `server_cert.pem`, `server_key.pem`, `client_cert.pem`, `client_key.pem`.

#### Шаг 3. Генерация ключа шифрования
Сгенерируйте симметричный ключ Fernet:
```python
# generate_key.py
from cryptography.fernet import Fernet
key = Fernet.generate_key()
with open("encryption_key.txt", "wb") as key_file:
    key_file.write(key)
```
```bash
python3 generate_key.py
```

#### Шаг 4. Запуск системы
Необходимо реализовать код компонентов и запустить их в разных терминалах:
1.  **Терминал 1 (Сервер 1):** `python3 server.py 5001`
2.  **Терминал 2 (Сервер 2):** `python3 server.py 5002`
3.  **Терминал 3 (Координатор):** `python3 coordinator.py` (порт 8000)
4.  **Терминал 4 (Клиент):** `python3 client.py`

#### Шаг 5. Демонстрация отказоустойчивости
1.  Выполните запрос клиентом — убедитесь, что ответил Сервер 1.
2.  Остановите Сервер 1 (Ctrl+C).
3.  Повторите запрос клиентом.
4.  **Ожидаемый результат.** Координатор обнаружит ошибку подключения к порту 5001 и автоматически перенаправит запрос на порт 5002. Клиент получит успешный ответ.
